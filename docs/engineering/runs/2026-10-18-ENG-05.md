## Token/cost telemetry (measured)
- **Available:** per-API-response token usage (`input_tokens`,
  `cache_creation_input_tokens`, `cache_read_input_tokens`,
  `output_tokens`) is written to the Claude Code session transcript
  (`~/.claude/projects/<project>/<session>.jsonl`). Summing unique
  message IDs works: at the point of measurement this session had 21 API
  responses, 85,129 cache-write, 2,251,463 cache-read, 42 uncached input
  and 8,298 output tokens.
- **Not available:** no cost or dollar field appears in the transcript;
  subscription limit usage isn't exposed to the session.
- The A/B evaluation in `GRAPHIFY_PILOT.md` can therefore use transcript
  token sums per session, but the totals are dominated by cache reads of
  the system prompt and conversation, so comparisons need separate
  sessions with the same model, effort and question.

## What is **not** evidence
- `graphify benchmark` reports "7.2x fewer tokens per query". It compares
  against reading the whole corpus (~32.7k tokens, estimated), which is
  not how Claude Code navigates (it greps and reads a few files). This is
  a vendor heuristic, not a measured saving.
- For the verified question, `grep -rn buildDecisionSequence src tests`
  returned every caller (including the ones the graph missed) in fewer
  bytes than the graph query. One question proves nothing either way.
- **No token saving has been measured.** The controlled evaluation was
  not run.
